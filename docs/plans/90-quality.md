# 90 · 质量门禁与测试策略

## 门禁（每次改动、每个域交付时）

```bash
cargo check --all-targets          # 零错误
cargo clippy --all-targets         # 零错误；不得新增告警（现有 lint 配置见 Cargo.toml）
cargo test                         # 全绿
cargo run                          # 手动冒烟：能到 Title（M1 起）
```

## 测试策略

1. **纯逻辑层优先**：生成、调度、消息、战斗公式一律写成不依赖 `World` 的纯函数/
   结构体，用普通 `#[test]` 覆盖。这是本项目可测试性的第一原则。
2. **确定性对拍**：涉及随机的测试固定种子 + 多种子性质测试（连通性、无 panic、
   数值域）双管齐下。
3. **Bevy 集成测试**：无渲染 `App`（`MinimalPlugins` + 被测插件）跑 `app.update()`
   断言资源/组件状态；不开窗口。
4. **与 SPD 对拍**：数值公式（命中、伤害、掉落率）移植时在测试注释里标注
   Java 源文件与行号，便于回查。

## 代码规范

- 沿用根 `Cargo.toml` 的 clippy lint 集（`unsafe_code = "deny"` 等）。
- 模块骨架：`领域.rs` 入口（Plugin + 公共 API）+ `领域/` 子模块；
  跨域只经入口 re-export 的类型交互。
- 注释：语义/换算/与 SPD 差异处必须注释（尤其 Rect 开闭区间、角度约定、
  时间取整这类"沉默陷阱"）；不写叙事式废话注释。
- 命名：SPD 概念保留英文原名（Terrain、Feeling、LimitedDrops…），
  文档与注释用中文。

## 多智能体纪律

- 领域计划的"文件所有权"是硬边界；越界改动一律回退重做。
- 交付物必须包含：改动摘要、测试结果原文、计划文档进度勾选。
- 协调者在合流时统一跑门禁；红灯不合流。
